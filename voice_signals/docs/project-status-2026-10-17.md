## Резюме

Проект voice_signals находится в **хорошем состоянии**. Вторая итерация успешно завершена, инженерная база готова к интеграции реальных данных. 

**Основная идея проекта:** Анализ речевых сигналов человека для выявления его интеллектуальных способностей через собственный VAD-подобный алгоритм, использующий показатель Хёрста и modified R/S-анализ на основе методики Кузенкова (научный руководитель).

**Ключевое достижение Iteration 02:** Реализован piecewise linear fit для характерного времени T (вместо грубого argmax), что более точно следует методике из статьи Кузенкова/Логинова (2014).

## 1. Что реализовано

### 1.1. Алгоритмический стек

✅ **Energy VAD с гистерезисом**
- Двухпороговая детекция (вход 10 дБ, выход 6 дБ)
- Постобработка: минимальная речь/пауза 80 мс
- Детерминированный, без внешних ML-зависимостей
- Непересекающиеся сегменты через `SegmentRecord`

✅ **Modified R/S-анализ** (обязательная нелинейная ветвь)
- Методика Кузенкова/Логинова (2014): нормированный размах, геометрическая шкала τ
- Показатель Хёрста `H` через log-log регрессию
- **Новое:** Piecewise linear fit для характерного времени `T`
- Флаги валидности: `R² < 0.7` → warning, короткий ряд → `valid=False`
- Интерпретация: H ≈ 0.5 (броуновское), H > 0.5 (персистентность), H < 0.5 (антиперсистентность)

✅ **Унифицированная архитектура**
- `VadBackend` – базовый класс для всех детекторов
- Единые контракты: `SegmentRecord`, `FileAuditRecord`, `FrameFeatureRecord`, `ExperimentRecord`
- Общая временная сетка: `TimeGrid`, `compute_rms_frames`
- Config hash (SHA256) для воспроизводимости

### 1.2. Инструментарий

✅ **Синтетический корпус** (TASK-09)
- 4 типа событий: speech, silent_pause, hesitation, artifact
- SNR: 5/10/20/30 дБ
- Ground truth: `start_sec`, `end_sec`, `label`, `true_h`, `noise_level_db`

✅ **Аудит WAV** (TASK-01)
- Метаданные: sample rate, каналы, длительность, битность
- Энергетика: RMS, peak, crest factor, noise floor
- Флаги: clipping, low_energy, mostly_silent, unusual_sample_rate
- Отчёты: детальный CSV, сводка MD, issues-only CSV

✅ **Feature extractor** (TASK-02)
- RMS, energy (dB), zero-crossing rate, spectral flatness (упрощённая)
- Без numpy/scipy – чистый Python
- CSV-экспорт с таймкодами

✅ **Демонстрационный pipeline** (`demo_pipeline.py`)
- VAD → modified R/S → интерпретация H
- Проверка на Ru-Vegetables.wav

## 2. Литературная база

### Основная методика

📄 **Кузенков Н.П., Логинов В.М. (2014)**  
"Использование метода нормированного размаха при анализе речевых патологий неврологического генеза"  
Компьютерные исследования и моделирование, 2014

**Статус:** `docs/kuzenkov/crm358.md` – выжимка методики  
**Перенос в проект:**
- ✅ Алгоритмическая схема modified R/S
- ✅ Геометрическая шкала τ
- ✅ Piecewise fit для характерного времени T (реализовано в Iteration 02)
- ❌ Параметры записи (8 кГц, ФВЧ 80 Гц, окно 100 мс) **не переносятся автоматически**
- ❌ Клинические выводы статьи **не переносятся** на VAD

### Дополнительная литература (новая)

📄 **XXIX Всероссийский семинар "Нейроинформатика" (2021)**  
`docs/literature-review-neuroinformatics-2021.md`

**Ключевые идеи:**
- YOLOv4 + DeepSORT: window-based детекция, IoU 78.81%, F1 0.98
- Упругие карты для валидации малых выборок (суррогатные данные, 0.5×σ/1×σ/2×σ)
- Спайковые нейронные сети: энергоэффективность, временное кодирование признаков
- Нейросетевое декодирование vs центроиды: 100% vs 42-92% точность

**Применимость:**
- IoU-метрики для временных сегментов VAD
- Робастность через суррогатные данные
- Временная нормализация окон

📄 **HAR на видео (AIP 2025)**  
`docs/books/030020_1_5.0301806-summary.md`

**Ключевые идеи:**
- Конвейер: сегментация → признаки → классификация
- Semi-supervised learning для малой разметки
- Разделение handcrafted baseline / learned representation
- Robustness-срезы по условиям (шум, сцена, респонденты)

📄 **Wireless HAR (AIP 2026)**  
`docs/books/030033_1_5.0327756-summary.md`

**Ключевые идеи:**
- Мультимодальность (Wi-Fi CSI, FMCW, UWB)
- Deployment-метрики: latency, размер модели, энергопотребление
- Subject-level split (не frame-level!)
- Privacy-by-design

📄 **Emotion recognition на DEAP (AIP 2026)**  
`docs/books/050028_1_5.0328667-summary.md`

**Ключевые идеи:**
- Спектральные признаки: FFT, band power, spectral entropy
- Feature fusion + XGBoost/RF baseline (accuracy 87-90%)
- Subject-independent split критично для честной оценки

**Применимость:**
- Спектральные признаки в backlog (TASK-02 расширение)
- XGBoost/RF как табличный baseline после стабилизации

## 5. Критические блокеры MVP

### 🔴 Блокер №1: Отсутствие реальных данных

**Статус:** Нет доступа к реальному корпусу

**Последствия:**
- Невозможна честная оценка VAD
- Пороги energy VAD – только инженерные, не откалиброванные
- Метрики на синтетике не переносимы
- `ASSUMPTION: sample_rate 16000` не проверено

**Действия:**
1. Запросить у научного руководителя доступ к реальному корпусу
2. Уточнить параметры: sample rate, каналы, длительность, формат
3. Уточнить метаданные: subject_id в именах файлов, task_type
4. Запустить TASK-01 (аудит) на реальных данных
5. Зафиксировать фактический sample rate, снять `ASSUMPTION`

### 🔴 Блокер №2: Отсутствие gold-разметки

**Статус:** Нет размеченных речевых сегментов

**Последствия:**
- Невозможна оценка precision/recall/F1
- Невозможна калибровка порогов VAD
- Невозможно сравнение с WebRTC baseline
- Невозможна проверка связи H/T с когнитивными характеристиками

**Действия (TASK-08):**
1. Подготовить инструкцию разметки:
   - Таксономия: `speech`, `silent_pause`, `hesitation`, `artifact`
   - Дыхание → `artifact`
   - Лексические заполнители не выделяются отдельно
2. Настроить Label Studio (устанавливает пользователь)
3. Пилотная двойная разметка (2 аннотатора, минимум 10-20 файлов)
4. Расчёт IAA (Cohen's κ ≥ 0.8)
5. Adjudication расхождений
6. Создание test split (subject-level!)

### 🔴 Блокер №3: Нет WebRTC baseline

**Статус:** Интерфейс готов, реализация отсутствует

**Последствия:**
- Невозможно сравнение собственного VAD с промышленным решением
- Нет референсного baseline для метрик
- Нет проверки гипотезы "H/T улучшают качество VAD"

**Действия (TASK-06 полная):**
1. Реализовать `WebRtcVad(VadBackend)`
2. Параметры: aggressiveness 0..3
3. Явная конвертация sample rate (WebRTC требует 8/16/32/48 кГц)
4. Экспорт в `SegmentRecord`
5. Опционально: Silero адаптер (при наличии torch)

### 🔴 Блокер №4: Нет subject-level split

**Статус:** Алгоритм не реализован

**Последствия:**
- Случайный frame-level split завысит результаты
- Утечка данных между train/validation/test
- Невозможна честная оценка обобщения на новых респондентов
- Результаты не будут научно валидными

**Действия:**
1. Реализовать `split_by_subject_id()` в `src/voice_signals/`
2. Стратифицированный split: 60% train / 20% validation / 20% test
3. Фиксация seed для воспроизводимости
4. Проверка: нет пересечений subject_id между частями
