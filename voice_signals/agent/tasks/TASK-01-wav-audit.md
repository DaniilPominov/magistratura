# TASK-01. Модуль аудита WAV-файлов

Роль: Data engineering agent. Файл результата: `wav_audit.py`.

**Статус:** ✅ Базовая версия завершена (работает на синтетике)  
**Блокер:** ⏳ Нет реального корпуса для проверки на реальных данных

## Цель
Автоматический аудит аудиофайлов до разметки и обучения. Неизвестны фактические sample rate, длительности, клиппинг, согласованность метаданных и распределение по респондентам.

**ВАЖНО:** Текущее допущение `ASSUMPTION: sample_rate 16000` должно быть проверено на реальном корпусе и обновлено в `configs/default.yaml`.

## Вход
- Каталог с WAV или список путей.
- Опционально таблица `file_path -> subject_id -> task_id -> task_type`.
- Если таблицы нет: извлечение `subject_id`/`task_id` из имени файла по настраиваемому regex, с пометкой `inferred`.

## Выход
- `reports/wav_audit.csv` (или Parquet) — по записи на файл.
- `reports/wav_audit_summary.md` — сводка.
- `reports/wav_audit_issues.csv` — проблемные файлы.

Обязательные поля: file_path, file_name, subject_id, task_id, task_type, duration_sec, sample_rate, channels, bit_depth, encoding, peak, rms, crest_factor, clipping_count, clipping_ratio, silence_ratio, low_energy_ratio, estimated_noise_floor_db, has_dc_offset, is_mono, is_stereo, unsupported_format_flag, quality_flags.

## Шаги
1. Рекурсивный поиск `.wav`/`.WAV`.
2. Метаданные через `soundfile` (sample rate, каналы, длительность, subtype) блоками, без загрузки всего файла в RAM.
3. Энергетика: peak, RMS, crest factor, доля тихих кадров, выбросы выше clipping_threshold.
4. Шумовой пол: 10-й перцентиль энергии окон.
5. Флаги: нулевая длительность, sample rate вне ожидаемого диапазона, стерео при ожидаемом mono, клиппинг, полная тишина, высокая доля низкой энергии, повреждённый заголовок.
6. Сводка: число файлов, суммарная длительность, распределения sample rate и каналов, число респондентов и заданий, медианная длительность, доля проблемных, топ-20 худших.

Пороги (калибруются): clipping 0.999, silence -50 dBFS, low energy -40 dBFS.

## Конфиг
```yaml
audit:
  expected_sample_rates: [8000, 16000, 22050, 44100, 48000]
  expected_channels: 1
  min_duration_sec: 1.0
  max_duration_sec: 1800.0
  clipping_threshold: 0.999
  silence_threshold_db: -50
```

## Критерии приёмки
1. Обрабатывает синтетический каталог не менее 50 файлов.
2. Не падает на пустых, коротких, стерео и разночастотных файлах.
3. Детерминированный отчёт при одинаковом входе.
4. Работает блоками.
5. Понятные `quality_flags`.
6. Явно различает `UNKNOWN` и реальные значения.

## Тесты
- 16 kHz mono читается корректно.
- 48 kHz stereo при ожидаемом mono помечается.
- Клиппинг даёт ненулевой `clipping_count`.
- Полная тишина даёт `silence_ratio` близкий к 1.
- Файл короче 100 мс обрабатывается без ошибки.
- Повреждённый WAV попадает в issues, пайплайн не падает.
- Integration: запуск на корпусе TASK-09 формирует полный отчёт.

## Ошибки, которых избегать
- Загружать весь корпус в память.
- Считать, что все файлы 16 kHz.
- Смешивать subject_id из имени файла с подтверждённой метаданной.
- Игнорировать стерео.
- Не сохранять версию конфига аудита.

## Инструкция агенту
Реализуй модуль аудита WAV-файлов. Принимает каталог или список файлов, читает метаданные потоково, считает энергетику, обнаруживает клиппинг, тишину и аномалии, сохраняет CSV/Parquet и Markdown. Не предполагай sample rate, число респондентов или структуру имён. Неизвестное помечай как UNKNOWN или извлекай по regex с флагом inferred. Добавь unit-тесты на синтетических WAV.
