# TASK-00. Bootstrap проекта и контракты данных

Роль: Project infrastructure. Это обязательное предусловие перед TASK-09
минимальной версией.

## Цель

Создать минимальный воспроизводимый каркас проекта, чтобы остальные задачи
реализовывались не как изолированные скрипты, а как совместимые модули.

## Результат

```text
pyproject.toml
src/
  schemas.py
tests/
configs/
data/synthetic/
reports/
scripts/
docs/contracts.md
```

Зафиксировать:

- поддерживаемую версию Python;
- runtime- и test-зависимости;
- команду запуска тестов;
- формат YAML-конфигураций;
- единицы времени: секунды с плавающей точкой;
- классы MVP: `speech`, `silent_pause`, `hesitation`, `artifact`;
- правила `UNKNOWN`, `inferred`, `is_pseudo_label`;
- версионирование модуля и конфигурации.

## Контракты

Реализовать типизированные структуры для:

- `FileAuditRecord`;
- `FrameFeatureRecord`;
- `SegmentRecord`;
- `ExperimentRecord`.

Минимально проверить:

- сериализацию и обратную загрузку;
- обязательные поля;
- допустимые метки;
- `start_sec >= 0`, `end_sec > start_sec`;
- отсутствие пересечения сегментов в валидаторе или отдельной функции.

## Критерии приемки

1. Чистая установка зависимостей выполняет smoke-test импорта.
2. `pytest` запускается одной командой.
3. Контракты используются из единого модуля, а не дублируются по задачам.
4. Конфигурация имеет стабильный hash.
5. Проверки не требуют реального или внешнего аудио.
