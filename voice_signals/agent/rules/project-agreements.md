# Глобальные правила для всех ИИ-агентов

Эти правила должны вставляться в контекст каждому агенту.

## Правило 1. Не выдумывать свойства реального датасета

Пока данные не получены, все предположения о частоте дискретизации, длительности, количестве файлов и метаданных должны маркироваться как допущение.

Формат маркировки:

```text
ASSUMPTION: ...
UNKNOWN: ...
TODO_AFTER_DATA_AUDIT: ...
```

## Правило 2. Работать сначала на синтетических и публичных данных

Любой модуль должен быть проверяем до получения реального корпуса. Для этого используется синтетический генератор речи, пауз, гезитаций, дыхания и артефактов.

## Правило 3. Бюджетное ограничение на внешние сервисы (обновлено 31.10.2026)

**Ответ научного руководителя (31.10.2026, вопрос 3 в `docs/questions-for-advisor.md`):**
правовых/этических ограничений на использование внешних сервисов нет —
допустимо использовать всё, что доступно для достижения результата. Единственное
реальное ограничение — финансовое: проект не может позволить себе платные
облачные сервисы.

```text
RAW_AUDIO_EXTERNAL_UPLOAD = allowed
EXTERNAL_COMPUTE_BUDGET = free_tier_only  # Google Colab free tier + локальный запуск
```

Разрешено:

- любая обработка (ASR, VAD, ML-инференс) на **бесплатных лимитах Google Colab**;
- любая обработка **локально** (на машине разработчика, без внешних сервисов);
- синтетические данные, анонимизированные метаданные, признаковые матрицы.

Не разрешено (по финансовым, не правовым причинам):

- платные облачные API (Google Speech-to-Text, Azure Speech, Yandex SpeechKit
  и т.п. вне бесплатных квот);
- платный GPU/compute (Colab Pro, облачные VM с оплатой, hosted inference
  тяжёлых моделей типа Silero через платный API);
- любой сервис, требующий оплаты за использование хотя бы в перспективе
  обработки полного корпуса.

Перед использованием любого внешнего сервиса агент должен проверить, что он
укладывается в бесплатный лимит Colab или выполняется локально. Если сервис
требует оплаты — не использовать, даже если он технически удобнее.

(Прежняя формулировка `RAW_AUDIO_EXTERNAL_UPLOAD = forbidden_until_legal_review`
снята этим ответом; правовой/этический блокер закрыт, остаётся только
бюджетный.)

## Правило 4. Все числовые модули должны иметь детерминированные тесты

Каждый алгоритмический компонент должен проверяться на сигналах с известным поведением:

- синус;
- белый шум;
- розовый шум;
- дробный гауссовский шум;
- хаотический ряд;
- периодический сигнал;
- речеподобные сегменты;
- тишина;
- транзиентные шумы.

## Правило 5. Не смешивать техническую задачу VAD и когнитивную задачу

На этапе реализации сегментатора нельзя формулировать результаты как «модель определяет интеллект». Корректная формулировка:

```text
Модель сегментирует речевые события.
Полученные признаки могут использоваться для дальнейшего исследования ассоциаций с результатами когнитивных тестов.
```

## Правило 6. Любой change должен быть привязан к метрике

Если агент меняет архитектуру, признаки, пороги или постобработку, он обязан указать, какая метрика проверяется:

```text
false_pause_precision
hesitation_recall
pause_duration_bias
macro_F1
calibration_ECE
downstream_Spearman
```
